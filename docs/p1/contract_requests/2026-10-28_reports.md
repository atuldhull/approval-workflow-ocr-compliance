# Report types, report catalogue and CSV download — three-way approval request

Date: 28 October 2026. P3. Status: **approved by Person 1, Person 2 and Person 3 on 2026-10-28**. The regenerated OpenAPI is committed on its own so it can be reviewed, approved or reverted independently of the analytics code.

## Why this is needed

`GET /api/reports/{report_type}` knew one type, `pendency`. The problem statement asks for EVC status, undertaking compliance, overdue cases and region-wise performance reports with a download (F3, B1, B2, B4). The dashboard also needed breakdowns by institution, time in the current stage and bottleneck stages. No event schema, port, shared type, enum or fake changes; permissions reuse `analytics.report` (officers and the auditor), so policy.py and the Cerbos policies are unchanged.

## Generated OpenAPI changes

Refreshed with `python scripts/check_contracts.py --write` (Python 3.12), no hand edits:

- `GET /api/reports` (new) → the report catalogue: `[{type, title, source, columns: [{key, label}]}]`. Same permission and scoping as the reports themselves; institutions get 403.
- `GET /api/reports/{report_type}`: `report_type` is documented as one of `pendency`, `evc_status`, `undertakings`, `overdue`, `region_performance`; unknown types stay 404 (not 422) so the list can grow without a schema change. New query parameter `format` (`json` | `csv`, default JSON); `Accept: text/csv` also gives CSV. The 200 response documents both media types.

## Report bodies

Every report returns `type, title, source, columns, scope {region, as_of?}, rows, total, coverage {note, unhandled_event_types, skipped_versions}, ledger_head {seq, entry_hash}, snapshot_hash`. Reports that age something (`evc_status`, `undertakings`, `overdue`, `region_performance`) state `scope.as_of`, the IST date they were computed for; the snapshot hash covers it, so the same ledger on the same day gives the same hash. `pendency` is unchanged apart from the added `title`, `source` and `columns`, and its hash still equals `GET /api/dashboards/pendency`.

- `evc_status`: per region — requests, queued, proposed, published, upcoming visits, done, cancelled, overdue, completion rate.
- `undertakings`: per region, obligation kind and status — obligations, overdue, evidence awaiting an officer, met late.
- `overdue`: one row per open clock that is breached or past its due date — case, region, rule, owner role, due date, days overdue, clock status, escalation level (highest alert level for the current due date).
- `region_performance`: per region — cases in process, median and average age, median days in the current stage, overdue clocks, alerts, share acknowledged before the next level.

The CSV has the same columns as `columns`, then the report title, source, region, as-of date, ledger entry and snapshot hash. Text cells that start with `= + - @` are prefixed with `'` so a spreadsheet never runs them.

The dashboard (`GET /api/analytics/dashboard`, untyped response) gains two sections: `flow` (time in current stage, cases and median days per stage, bottleneck and slowest stage) and `institutions` (applications, in process and overdue clocks per institution, top ten).

## Extension point

A report is one builder function plus one `Report(title, source, columns, build)` entry in `REPORTS` (`backend/app/analytics/reports.py`); the endpoint, catalogue, CSV and screen take it from there. The document-validity report is added that way once the document-validity obligations land; regenerate the OpenAPI so the `report_type` description lists it.

## Impact if refused

The new report types are additive; reverting the OpenAPI commit only removes them from the published contract and the catalogue endpoint. The Reports screen would show pendency only.
