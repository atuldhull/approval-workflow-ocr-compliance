## HTTP handoff

All routes retain the existing `/api` prefix and X-Demo identity. Use POST `/cases/{id}/actions` with `action=record_deficiency`, the current `expected_version`, a YAML-listed `reason_code`, and `payload={"item_keys":["DEMO_CORE_REFERENCE"]}`. The optional `note` is protected by NotesPort. Read GET `/cases/{id}/deficiencies` for round/item UUIDs and the response-window assumption, then call actions with `action=submit_compliance` and `payload={"responses":[{"item_id":"<returned item UUID>","response_ref":"<opaque response UUID>"}]}`. Supply exactly one mapping for each OPEN item. A response may answer several items, but each mapping is explicit.

POST `/cases/{id}/deficiencies/{round_id}/review` accepts `expected_version`, `decisions=[{"item_id":"<UUID>","state":"ACCEPTED","reason_code":"DEMO_RESPONSE_ACCEPTED"}]`, and optional protected `note`. Partial review is permitted; all-accepted closes the round and stamps closed_at from ClockPort. REJECTED is unresolved; correction by an officer is audited. Replacement evidence/resubmission after rejection needs a separately agreed timer policy, rather than silently restarting an expired/closed clock. Review advances the optimistic version, not the stage. Fetch the current version before the next action. Institutions can read their own rounds but cannot review; RO reads retain region scoping.

The second round is a new record_deficiency transition from RESCRUTINY after closure of the first. Existing mandatory/conditional route stages remain identical; the reusable deficiency template gains RESCRUTINY as a source. Counts in prior acceptance_report.md remain historical to its commit, since the valid/invalid matrix membership now reflects this additional configured edge.
