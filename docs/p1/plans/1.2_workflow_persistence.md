## Storage and startup behavior

| Table | Important constraints and data |
|---|---|
| wf.ruleset | Deterministic UUID, unique key, revision/version, five allowed lifecycle statuses, 64-character source checksum, demo_only, source manifest/provenance and opaque created/approved references. Approval timestamp/reference must occur together. |
| wf.route_def | Deterministic UUID, matching ruleset UUID/key FK, unique (ruleset_key, route_id), category, normalized stage/when list and nullable explicit route citation. |
| wf.transition | Deterministic UUID per ordered expanded edge; route FK, unique route/position, action/from/to, roles/guards/timers/letter JSON, reason requirement and original template definition/selectors. These are potential guarded edges, not unconditional execution permissions. |
| wf.case_state | application_id is the unique primary key and therefore has its own PostgreSQL unique index. Composite pinned route/key FK and lookup index, current stage/status, positive version; SQLAlchemy checks/increments version on ORM updates. A wf-owned trigger rejects application/key/route repinning even through direct SQL. |
| wf.stage_visit | Existing table/data preserved; stored left_at renamed exited_at, with compatibility synonym, outcome/reason_code/note_ref added. Existing application_id index retained. record_exit obtains ClockPort time and refuses a second exit; command authorization/ledger remain the caller's responsibility. |

Workflow's existing auto-discovered API router registers sync_at_startup. The app's import/model/wiring phases have no database side effects; a real ASGI startup context performs the sync after normal migrations. The loader owns no commit and touches only definition tables. A transaction advisory lock serializes concurrent starts; the surrounding transaction commits the entire source set or rolls it all back. Matching hashes skip all writes and do not read time, preserve approval metadata, and leave cases/visits alone. New imports use one ClockPort instant and an opaque deterministic bootstrap reference.

Checksums are independent of the checkout's absolute path and include relative file names plus file-byte hashes, including overlay dependencies. A fresh parser avoids pairing stale cached content with a new hash; a second manifest check rejects source changes during parsing. Demo overlays are skipped outside demo mode; a missing or demo-only default fails startup. The importer is not a lifecycle approval service and never converts source status verified_text into APPROVED/ACTIVE. Existing HTTP responses remain unchanged; future command/approval integration is still separate work.
