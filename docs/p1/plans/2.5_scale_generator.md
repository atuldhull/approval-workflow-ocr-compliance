# Scale generator plan

Read AGENTS, both reference documents' generator sections, seed_demo.py, the proposed answer-key schema/models, the current workflow/deficiency APIs and route acceptance support.

Generate canonical JSON with a local random.Random(seed), UUID5 DEMO identities and a fixed logical ClockPort-compatible clock. Use largest-remainder balanced category allocation across the existing 22 routes, shuffled by seed; record the assumed frequencies. Produce institutions, application commands, deficiency rejection/resubmission chains, EVC waits, terminal reject/withdraw outcomes and matching answer-key expectations. Reserved extensions stay empty. Never claim letter issuance or OCR/tamper coverage.

Load institutions only through the existing P1 bootstrap (wf.institution; no institution-create API exists), then create, provide prerequisites, submit, act and review through the real HTTP API. Maintain logical-to-runtime ID mappings rather than depending on generated database UUIDs. Require a caller-supplied logical clock and trusted server assignment/applicability facts; do not weaken guards or change P2/P3 code. Exercise real auth, deadlines, ledger and engine in the integration test. No direct SQL writes to other schemas or application/state tables.

Test five seeds, byte identity, seed differences, counts/mix/schema semantics, invalid inputs, CLI artifacts and seed-1 API replay with stage/status/response/timer evidence. Run the full suite and standing contract/head checks, then commit/push only person-1. Record measured results and limitations below.

Every seed has 300 institutions, 9 synthetic ROs, 600 applications, all 22 categories and zero letter expectations. Item count equals round count because each round has one controlled item. Clock counts include open/pause/resume/close expectations.

The 22-application replay passed using real auth, deadlines, ledger and workflow, with a controlled ClockPort and explicit DEMO assignment/SHC facts. A transparent test observer delegates all deadline calls to P2's real engine and compares their exact operation/rule/time/order to the key. The final suite also runs the full default-size 600-application seed-1 replay.

Coverage limits: no letter issue/approval path (previous contract blocker); EVC stage holds are simulated rather than scheduler rows; P2/P3 extensions remain empty/NOT_SUPPLIED. Remote replay needs an approved logical-clock transport. No shared contracts, API schemas, P2/P3 modules, rulesets or migrations are changed; no new endpoints/events/tables. The new bootstrap writes only existing P1 institution rows.
