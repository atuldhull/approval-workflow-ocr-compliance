## Implementation

1. Add backend/app/evc/selector.py with the literal label **SIMULATED authorised selector (stand-in)**. Expose pure `select_panel(request, date, slot_part)` using immutable selector/eligibility/history snapshots. No database, port lookup, random source, clock, mutations or assignment publication in the pure function. Add a separate DB adapter for the future scheduler and read-only API.
2. Reuse eligible_experts for active/COI/availability/region/reservation exclusions. Neither ranking nor a shortage may admit a conflicted or otherwise ineligible expert. Candidates must also satisfy the configured minimum expertise-match count.
3. Use lexicographic criteria, documented in this exact order: hard eligibility; descending count of distinct requested expertise tags matched; ascending assignment workload; oldest prior assignment date (never assigned first); ascending expert UUID as final stable tie-break. Do not obscure priorities in a weighted total. The response includes the criterion order, matched tags and each criterion's machine-readable score.
4. Workload counts each stored assignment/expert membership once, including proposed/published and future commitments, consistently with conservative eligibility reservations. Rotation considers only dates earlier than the selection date; future assignments do not masquerade as past rotation. Same-day commitments still affect workload. Contradictory duplicate history facts are rejected; exact duplicates cannot inflate workload. Future scheduling must recheck/reserve in its own transaction.
5. Put the configurable selector policy inside existing expert_pool YAML/RuleSet.expert_pool, inherited by r3-DEMO and saved in the existing immutable ruleset snapshot. Demonstration defaults: version DEMO_SELECTOR_V1, panel_size 3, required_expertise_tags [DEMO], category_expertise_tags {}, minimum_expertise_matches 1, source_status DEMO_ASSUMPTION, assumption_code SELECTOR_POLICY_UNCONFIRMED. Category mappings are explicit optional overrides, validated against route IDs. No hardcoded category-to-domain mapping is invented. Existing expert policies without a selector remain valid for pool management; selector calls fail explicitly when their policy is missing.
6. Return either exactly N distinct expert IDs or an explicit INSUFFICIENT_CANDIDATES result with an empty panel; keep the qualified ranking for explanation. No silently partial panel. Include selector_label, simulation_status SIMULATED, source_status DEMO_ASSUMPTION, assumption_code, policy version, pinned ruleset key, date/part, requested size and scores. Identity remains P3_USER_REF_UNVERIFIED as in the existing pool API.
7. Add GET /api/evc/requests/{id}/panel-preview?date=YYYY-MM-DD&slot_part=AM|PM. Reuse evc.expert.read and CasePort/AuthzPort case.timeline authorization. Institutions cannot access expert selection; ROs must own the request's authoritative case region. For cross-region policies, RO preview fails closed (SELECTOR_CROSS_REGION_SCOPE_FORBIDDEN) instead of exposing foreign expert identities or returning a differently filtered panel than the scheduler. Existing global pool readers can inspect the full configured policy. Preview operates on QUEUED/PROPOSED requests and changes no data; no new event or migration is needed.
8. Test repeatability and permutation invariance, every hard exclusion, expertise priority, workload priority, rotation and UUID ties, duplicate history, future-history handling, missing/invalid policies, exact-N/shortage behavior, pinned selection policy, API label/scores, authorization and zero writes. A pure 100-request benchmark updates explicit in-memory assignment facts between requests and compares workload spread/variance against naive first-fit on the same eligibility inputs. Use equally qualified fictional DEMO experts; report measured counts, without claiming universal fairness when expertise priorities differ.
