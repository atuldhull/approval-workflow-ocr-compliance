# Runtime guard facts plan (trusted server loader + published-EVC completion)

Read guards.py (read_facts, register_fact_loader, every registered guard), commands.py (GuardFacts, Payload, LetterPayload), engine.py (_context, plan_transition, _timers, letter registration), case_service.py, committee.py, deficiency.py, wiring.py, the intake models/service, EvcPort and evc/README, CompliancePort and compliance/service.py (letter provenance), the r1 routes.yaml/deadlines.yaml, ASSUMPTIONS WE-001/TG-004/TG-005/CM-005/SCHED-003 and every test that injects GuardFacts. Starting point: integration/person-1 at 07ed9bc.

## Problem

`guards.read_facts` used `GuardFacts()` when no loader was registered, and only tests registered one. In the running app every guard that needs assignment, applicability, decision, letter, live-clock or second-approval facts therefore refused with `GUARD_CONTEXT_UNAVAILABLE`/`APPLICABILITY_UNAVAILABLE`: no case could move past submission. Separately, `complete_evc` accepted a QUEUED/PROPOSED request (`evc_request_open`), so a visit could be "completed" before it had a published date and panel.

## Implementation

1. `app/workflow/facts.py` is the trusted loader, installed by `workflow.wiring.wire()` through `guards.register_default_fact_loader(facts.load)`. An explicitly registered `_fact_loader` (unit tests, the logical-clock replay CLI) still takes precedence; with neither, guards fail closed as before. Nothing is read from the command payload as a fact source.
2. Fact sources (labels refer to ASSUMPTIONS GF-00x):

| GuardFacts field | Source in the running app |
|---|---|
| missing_item_keys, provided_item_keys, checklist_complete, dsc_required, dsc_present | unchanged: pinned intake checklist + `wf.application_item` + `wf.application.dsc_present` (read_facts, DRAFT only) |
| open_item_count, deficiency_status, reason_codes, item_refs, response_refs | unchanged: `wf.deficiency`/`wf.deficiency_item` + pinned deficiency config (deficiency.read_facts) |
| evc_request_status | unchanged: `port(EvcPort).status(...)` while the case is in EVC |
| has_assignment | GF-001: actor is a member of an ACTIVE committee workspace whose type staffs the current stage |
| applicability | GF-002: an as_applicable stage applies once a committee workspace of that type has been formed for the case |
| decision_refs | GF-003: head report version of each ACTIVE committee staffing the current stage |
| confirmed_letter | GF-004: academic year from `wf.application`; PORTAL_EVENT issue date = today (IST) from ClockPort; type/lists_deficiencies checked against the transition, f_no and CONFIRMED_FACT provenance checked by CompliancePort in the same transaction |
| live_clock_rules | GF-005: replay of the pinned transition timers over this case's own stage-visit history (submit + every exited visit's outcome); P2 tables are not read (TG-004) |
| second_approval_required | GF-006: pinned `guard_facts.revert_second_approval_required` (DEMO ASSUMPTION, false); a ruleset pinned without it refuses with APPROVAL_POLICY_UNAVAILABLE |
| second_approver_refs | none: no approver directory exists, so a required second approval refuses with APPROVAL_CONTEXT_UNAVAILABLE |

3. New guard `evc_schedule_published`: EVC_REQUEST_NOT_ACTIVE unless the request is QUEUED/PROPOSED/PUBLISHED, then EVC_SCHEDULE_NOT_PUBLISHED unless PUBLISHED. Both `complete_evc` templates use it (the onward `evc_complete` previously had no EVC guard at all). `evc_request_open` stays registered for older pinned definitions.
4. `LetterPayload.f_no` (optional, ≤100 chars) is passed to `LetterIn.f_no`; CompliancePort requires it for a PORTAL_EVENT issue date, so in-workflow letters can reach the real compliance module. Issuance itself is still behind `WF_ENABLE_LETTER_ISSUANCE` (default off) because contract request 2026-10-26_letter_issuance (ruleset_rev on LetterIn) is still open.
5. r1 routes.yaml: `guard_facts` block and the two complete_evc guard lists. The source checksum changes; as with earlier approved r1 edits, a fresh disposable database is required and cached checksums keep rejecting changed sources. No route stage list, timer, role or P2 deadline rule changes.

## Tests

- `backend/tests/test_guard_facts_runtime.py` (no injected loader; asserts `_fact_loader is None` and the wiring default is installed): NEW_PROGRAMME from intake submit → SCRUTINY (refused ASSIGNMENT_REQUIRED until a scrutiny workspace is formed) → deficiency → compliance → start_rescrutiny → acceptance auto-advance to EVC → complete_evc refused ASSIGNMENT_REQUIRED, then EVC_SCHEDULE_NOT_PUBLISHED → experts, propose, publish → complete_evc → LOA through the real CompliancePort, for both the skipped-SHC and SHC-committee paths. Refusals: superseded report as decision (DECISION_NOT_AUTHORISED), wrong academic year / back-dated PORTAL_EVENT date (LETTER_DATA_NOT_CONFIRMED), EOA with LOA data (LETTER_DECISION_MISMATCH). Live-clock replay closes AICTE_PROCESSING MET and INSTITUTION_RESPONSE WAIVED on a reject inside the response window; revert refuses APPROVAL_POLICY_UNAVAILABLE / APPROVAL_CONTEXT_UNAVAILABLE when the pinned policy is missing / requires a second approver; assignment is per stage and per member, also in the case's available_actions.
- `tests/acceptance/test_evc_queue.py`: tests that complete an EVC now propose+publish first (and assert the unscheduled refusal); `route_support.py` and `test_workflow_engine_core.py` pure fixtures report PUBLISHED. `test_workflow_case_api.py` expects ASSIGNMENT_REQUIRED from the trusted loader and GUARD_CONTEXT_UNAVAILABLE only with no loader at all.
- The 600-case replay never calls complete_evc (it advances through EVC) and keeps its explicit DEMO loader, so it is unchanged.

## Limits

`advance` out of EVC (to SHC) is not EVC-guarded; it is the existing template shared by all stages and was not in scope. Committee assignment facts are not wired into P3's `AUTHZ_REQUIRE_ASSIGNMENT` gate (policy.py), which still refuses committee case access when that switch is on. Letter issuance date/provenance beyond PORTAL_EVENT=today depends on P2's confirmed facts.
