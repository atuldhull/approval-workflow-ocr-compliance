# 1.3 Workflow engine plan and integration contract

25 October 2026. Implement typed commands, a pure selection/guard core and handle(uow, command), then an execute(command) wrapper using the existing unit_of_work. Use persisted wf definitions and shared ports for other owners. No public HTTP endpoint or P3 policy edit. Contract authorization for this task covers new wf.* schemas only; ports/types/enums/fakes/OpenAPI stay unchanged.

Resolve ownership/region through CasePort only to construct ResourceRef, then authz.check is the first command decision before case_state is locked/read. Reject actor/principal mismatch, stale versions, invalid stage/action combinations, unregistered guards, missing facts, ambiguous transitions and unavailable dependencies with explicit reason codes. Pinned definitions remain authoritative; RulesetPort supplies the pinned deadline rules only.

Workflow owns a SQLAlchemy Core view of the stable, jointly P1-owned wf.stage_visit schema, in storage.py. This is not a duplicate table/model or an import of intake internals. It writes only wf in the same transaction and is checked against actual mapped columns. Close one open visit, open one for a nonterminal target, and update the version once. Terminal statuses close the visit and clear current_stage; they are not invented Stage enum values. Stage UUIDs derive deterministically from application/version/target.

guards.py registers named pure predicates. A workflow-local authoritative fact-loader hook must supply missing checklist/deficiency/assignment/decision/applicability/clock facts; defaults are unknown, not true/zero. Those facts are not command payload fields. The existing tables/ports do not yet provide all of them. Missing live-clock facts for conditional close must fail cleanly; never inspect P2 tables directly. P3 must separately permit case.<canonical_action>; existing production policy intentionally denies unknown actions. These integration requirements do not prevent implementing/test-driving the engine with explicit fakes.

Typed payloads contain IDs, coded values and confirmed letter data only; note_body is the one explicit prose input and goes exclusively to NotesPort. Letter issuance flag WF_ENABLE_LETTER_ISSUANCE defaults false; letter transitions fail before mutations while disabled, not silently approve without issuing a letter. Enabling requires CompliancePort and independently confirmed decision data. DRAFT definitions are usable only in demo mode; non-demo execution requires APPROVED/ACTIVE and refuses demo-only rulesets.

Timer execution follows YAML order. command.now uses one ClockPort instant; letter.issue_date uses confirmed date at midnight Asia/Kolkata. Anchor.event_seq is null because the requested ordering appends workflow events after timers and the current Anchor contract explicitly permits null; no sequence is fabricated. LEGAL pause/resume is rejected as Conflict; downstream ContractError propagates cleanly. Missing ports/rules become coded validation failures rather than a 500.

Append wf.transition_applied for the case/version change, wf.stage_exited for the old visit and wf.stage_entered for a new nonterminal visit, in deterministic order. Each EventIn envelope carries reason_code/ruleset_rev/note references/hash; payload schemas reject free text. Existing submit uses wf.application_submitted with its unchanged schema plus stage_entered. No actual letter or P2 deadline state is claimed without the corresponding port call.

handle never commits and rolls back the entire session on any exception, even if its caller catches the error; execute owns the usual outer commit/close. Tests use transaction-aware test-local adapters around the supplied P2/P3 fakes (shared fakes remain unchanged), real PostgreSQL for state/visits, and actual ledger rows for separate schema/rollback checks. Cover every expanded edge on three representative routes, all invalid stage/action pairs, versions/replay, flags/guards/authorization, notes, deterministic listing, timer failures and ledger failure atomicity.

Run the full suite, contracts check and migration check before committing/pushing only person-1. No unapproved contract/runtime approval is inferred from a successful fake-based test.

list_available_actions accepts either an immutable CaseContext for pure tests or an attached CaseState model for the UI read layer. The latter resolves CasePort scope, checks application.read, assembles authoritative context and then checks each canonical case action. It performs no writes/time reads. Detached models fail with CASE_CONTEXT_REQUIRED rather than trying an implicit database connection. Guard facts are resolved for the supplied principal; callers never pass client-generated contexts over HTTP.
