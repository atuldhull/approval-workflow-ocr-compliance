## Version 1 grammar

Existing ruleset/revision/status/source/roles/routes/appeal and `clocks.on_submit` remain. The legacy top-level `transitions` key remains a list; it now lists reusable template names. Each route has `transitions` referencing the same YAML-anchored list, instead of copying transition bodies 22 times. `templates` maps names to the canonical transition objects below. Existing inline `from/to/roles/require/guard/timers` declarations are deliberately migrated in r1 to explicit, statically validated fields. Old action spellings `complete` and `authorised_revert` remain aliases, as does `scrutinise` for `advance`. No current Python consumer reads the old top-level transition bodies.

```yaml
grammar_version: 1
terminal_states: [APPROVED, REJECTED, WITHDRAWN]
auxiliary_stages: {DEFICIENT: SCRUTINY, RESCRUTINY: SCRUTINY}
resume_after: {RESCRUTINY: SCRUTINY}
templates:
  deficiency:
    action: record_deficiency
    from_stage: SCRUTINY
    to_stage: DEFICIENT
    requires_stages: [SCRUTINY]
    allowed_roles: [SCRUTINY_COMMITTEE]
    guards: [reason_code_present, deficiency_items_present]
    reason_codes_required: true
    timers:
      - {op: pause_internal, rule_id: AICTE_PROCESSING, anchor: null}
      - {op: open, rule_id: INSTITUTION_RESPONSE, anchor: command.now}
    emits_event: wf.transition_applied
    letter: null
transitions: &standard [submit, advance, deficiency, compliance, rescrutiny,
  to_evc, evc_complete, to_shc, loa, eoa, lod, reject, withdraw, revert]
routes:
  NEW_PROGRAMME:
    label: New programme / level in existing institution
    stages: [SCRUTINY, EVC, {stage: SHC, when: as_applicable}]
    transitions: *standard
```

Every template requires action, from_stage, to_stage, allowed_roles (nonempty existing Role names), guards (list of named predicates), reason_codes_required (boolean), timers (ordered list), emits_event (wf.* or evc.* token), and letter (null or typed object). Optional aliases, requires_stages and match_to are explicit fields, not arbitrary executable expressions. Unknown keys, stage names, actions, roles, guards, timer operations and anchors fail validation. YAML must be a mapping; unsafe YAML and duplicate mapping keys are rejected. There is no eval, SQL, import path or Python expression in the grammar.

### Stage lists and expansion

- Stage strings mean `when: always`. Mapping items use `{stage, when}`; the only conditions are always/as_applicable. Route order and when values are preserved. Duplicate/empty stage lists are rejected.
- SHC occurs iff EVC occurs, SHC must be as_applicable, EVC must be always, and SHC follows EVC. This is the existing Table 2.3 pairing, not a new APH route claim. No category-specific routes live in Python.
- DRAFT is an entry status, not a new Stage value. Terminal names must be existing APPROVED/REJECTED/WITHDRAWN ApplicationStatus values, distinct from Stage names; they have no outgoing edges and are not inserted into the route's stage list.
- `auxiliary_stages` activates a named Stage only when its anchor occurs in that route. `resume_after` maps an activated auxiliary stage back to the plan position from which its next stage is computed. Both maps use existing Stage names; no second stage enum is invented.
- `$first` resolves the first route stage. `$route` expands source stages to the ordered plan plus activated resume stages. `$active` includes all activated auxiliary stages too. A literal source can also be a list. `requires_stages` explicitly skips templates not applicable to that route, but the template is still globally checked for typos.
- `$next` resolves the next applicable plan stage after the source/resume anchor. Conditional stages create potential take/skip edges, stopping at the next mandatory stage. It never invents a terminal when the plan ends. `match_to` filters these edges to a named next stage for advance_to_evc/advance_to_shc. Empty expansion at the end is expected; declarations that name absent stages without an explicit requires_stages filter are rejected.
- `$last` expands to every stage which could be last after trailing conditional stages are skipped, including a resume stage if its anchor could be last. Such decision transitions require the at_last_applicable_stage guard. This supports a skipped terminal SHC without bypassing mandatory EC/COUNCIL.
- `$previous` is permitted only for revert, with previous_stage_visited and a mandatory coded reason. It expands only earlier plan positions (or the auxiliary anchor and earlier positions). The future executor must additionally verify actual visit history and any second approval. No terminal reopening is permitted in version 1; that requires an explicit future reviewed grammar change.
- The graph validator expands ordered templates for each route. It rejects unreachable declared/activated stages, no reachable terminal, and reachable stages with no path to any terminal. Guard predicates are not executed: reachability is structural potential reachability, not proof every dynamic guard combination succeeds.

### Standard actions and guards

| Action | Meaning | enums.py change for this static task |
|---|---|---|
| submit | DRAFT -> first stage, opens submit clocks | None |
| scrutinise / advance | scrutinise is an alias; advance to next applicable stage | None |
| record_deficiency | SCRUTINY -> DEFICIENT, reason/items, pause/open clocks | None |
| submit_compliance | DEFICIENT -> RESCRUTINY, response required, close/resume | None |
| start_rescrutiny | Officer-triggered alternative using the same response/clock guards | None |
| advance_to_evc | Next edge only when its target is EVC | None |
| complete_evc | Complete EVC before its next plan stage | None |
| advance_to_shc | Next edge only when its target is SHC | None |
| issue_loa / issue_eoa / issue_lod | Authorized typed letter decision at last applicable stage | None; existing LetterType values |
| reject / withdraw | Explicit terminal decisions with coded reason | None; existing ApplicationStatus values |
| revert | Earlier actually visited stage, coded reason | None |

No Action enum exists in contracts today; strings are checked against the P1 grammar vocabulary. Sharing a WorkflowAction enum later is a team choice, not necessary to validate YAML. complete/authorised_revert are compatibility aliases only, never new routes.

Guard vocabulary: application_is_draft, open_items_zero, actor_has_assignment, reason_code_present, deficiency_items_present, response_received, at_last_applicable_stage, decision_authorised, letter_type_matches_decision, previous_stage_visited, second_approval_if_required. These are predicate identifiers, not free text or eval expressions. Revert requires reason_code_present/previous_stage_visited; record_deficiency/reject/withdraw require reason_code_present. No APH reason-code catalog is invented: the future command must resolve an authorized code list, store prose through NotesPort and personal data through PersonalDataPort. Runtime guard implementation is outside this task.

| Guard | Required future evaluation (all guards are ANDed, in listed order) |
|---|---|
| application_is_draft | Locked application status is DRAFT, not a browser-supplied status. |
| open_items_zero | Authoritative open deficiency-item count for this case is zero; failed/missing reads cannot mean zero. |
| actor_has_assignment | Actor is assigned/authorized for this case/stage; supplements, never replaces, authz.check. |
| reason_code_present | A command reason code exists in the approved vocabulary; prose goes through NotesPort. |
| deficiency_items_present | Command contains nonempty structured items with valid requirement references. |
| response_received | Linked institution response exists (or is persisted by this command in the same uow). |
| at_last_applicable_stage | No mandatory or positively selected optional stage remains after the source/resume anchor. Missing SHC applicability decision fails closed; it must not silently mean skip. |
| decision_authorised | Confirmed decision and actor's approval authority are valid for the case, using team-approved policy. |
| letter_type_matches_decision | Template's letter type AND lists_deficiencies flag match confirmed decision data, not an unchecked UI boolean. Additional true/false variants may be separate named templates with this guard. |
| previous_stage_visited | Requested revert target is an earlier plan candidate and actually appears in persisted visit history. |
| second_approval_if_required | A separately attributed approval exists when configured policy requires it; no invented APH threshold. |

Optional applicability decisions, confirmed letter data and reasons are future command context, not Python expressions embedded in YAML. Static expansion intentionally includes both possible optional-stage branches. A runtime consumer must resolve them and reject missing/ambiguous guard context; it cannot execute every potential graph edge as an allowed action.

### Timers and letters

`timers` is a list of `{op, rule_id, anchor}`; close additionally requires outcome MET or WAIVED. op is open/close/pause_internal/resume_internal, matching DeadlinePort methods. `open.anchor` is command.now or letter.issue_date; others use null. letter.issue_date requires a letter on that transition. Every rule ID must be present in the same ruleset's parsed deadlines.yaml, including unselected templates. No P2 files are changed. Pause/resume require an INTERNAL rule. Submit's ordered open operations must agree with clocks.on_submit; this prevents two competing submit-clock configurations.

Close optionally sets `if_live: true` for terminal cleanup across RUNNING/PAUSED clocks; it skips absent/already closed clocks without reopening anything. This condition is declarative only: a P2-approved same-uow inspection port or published read-only view is required before runtime implementation (see contract request). Other operations cannot use if_live. All cleanup still belongs in the same command transaction, not an asynchronous worker.

command.now means the command's one ClockPort instant and anchor event sequence; letter.issue_date means the confirmed LetterIn date in the P2-agreed civil timezone, not a wall-clock read. Do not pause legal clocks. No EVC duration/rule is invented: complete_evc has no EVC timer until P2 supplies an agreed rule. Closing the processing clock on decisions is a configurable DEMO ASSUMPTION.

letter is null or `{type: LOA|EOA|LOD|LOR|CORRIGENDUM, lists_deficiencies: <bool>}`. issue_* actions require a non-null letter with matching type. Their configured decision status/roles/deficiency flag are DEMO ASSUMPTIONS, not invented APH law. Before runtime issuance, guard letter_type_matches_decision must verify confirmed command data, and P1 calls CompliancePort.register_letter with the rest of LetterIn. An EoA does NOT directly open EOA_DEFICIENCY_6M: P2's officer-confirmed obligation flow still owns that rule.

Every future command must authz.check first, validate guards/reasons/history, apply state+visits, call P2 timers/letter registration through ports, append ledger entries for every state change and enqueue mandatory outbox work inside one unit_of_work. Timer list order is stable. This document does not implement those commands, mandatory-event schemas or P3 idempotency.
