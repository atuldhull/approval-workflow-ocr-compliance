# Checklist read endpoints plan

Read backend/app/documents/README.md (the checklist gap: the ruleset loader exposes no document checklist, so P2 could not build a checklist view), intake rules/service/shapes, workflow/checklists.py validation and the pinned `source_metadata.intake` written by the loader. P2's documents module is not edited.

## Implementation

1. `GET /api/rulesets/{key}/checklists/{category}` (`ruleset.read`): the category's checklist as pinned in `wf.ruleset.source_metadata.intake` when that ruleset was loaded — status/label DEMO_ASSUMPTION, assumption refs, dsc_required and `{item_key, mandatory}` items. Unknown ruleset or category is 404.
2. `GET /api/applications/{id}/checklist` (`application.read` with the CasePort institution/region scope): the same items with the application's state per item (PROVIDED/MISSING and document_ref), against the pinned ruleset, or the default ruleset while the application is a draft (`pinned` says which), plus dsc_required/dsc_present, missing mandatory keys and a completeness flag. It reuses `intake.rules.plan(...)`, the data intake submission is checked against.

Both are read-only and return no personal data. P2 can join `document_ref`/item keys to its document records on its own side.

## Tests
