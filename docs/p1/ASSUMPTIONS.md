# P1 assumptions

## Answer-key proposal (24 October 2026)

- DEMO ASSUMPTION AK-001: proposal version `0.1.0` uses canonical UTC `YYYY-MM-DDTHH:MM:SSZ` logical instants supplied explicitly by a scenario/ClockPort. No wall-clock default is allowed. These are fictional scenario times, not APH dates.
- DEMO ASSUMPTION AK-002: one file contains one seed, one pinned ruleset key, and exactly one workflow expectation record per application. Category is the existing YAML route key; institution category is a proposed synthetic classification code, not an APH institution taxonomy.
- DEMO ASSUMPTION AK-003: RO identifiers are synthetic uppercase codes; nine official RO names/codes are not asserted. Stable UUIDs will be supplied by the future generator; the models create no random IDs.
- DEMO ASSUMPTION AK-004: counts are exact array totals, late/delay durations use elapsed seconds, and item states are snapshots at each loop's `as_of_clock`. A route plan retains SHC `as_applicable`; `expected_visited_stages` records the chosen path at `route_outcome.at_clock`.
- DEMO ASSUMPTION AK-005: P2/P3 reserved extension objects must currently be `{}`. Unknown extension fields are rejected until a reviewed schema version adds them. Empty means not supplied/not scored, never zero expected alerts or a passed tamper test.
- DEMO ASSUMPTION AK-006: illustrative 30-day AICTE_PROCESSING and 15-day INSTITUTION_RESPONSE expectations follow the existing demo-assumption YAML, not legal deadlines. Sample EVC dates and letters are fictional planted expectations, not implemented workflow behavior or APH requirements.
- DEMO ASSUMPTION AK-007: P3 compares exact clock operations/instants and stable expectation IDs; tolerance, alert/escalation dedup keys and ledger targets await team agreement. No production event types, new shared ports, or legal clauses are introduced by this proposal.

## Wireframe design assumptions (25 October 2026)

- DEMO ASSUMPTION WF-001: target screen visibility and write permissions in wireframes.md are proposals using existing roles. Committee assignment, regional scope, EVC publish authority and ruleset approval/separation of duties require P3 policy agreement; they are not today's implemented policy.
- DEMO ASSUMPTION WF-002: no api_plan.md or numbered future prompt schedule exists. The literal label "TO BE BUILT in prompt X.Y" means an unassigned future integration task. Only Work Pack 1.2 endpoint patterns are specified as calls; missing reads/committee/review integrations receive no invented URL.
- DEMO ASSUMPTION WF-003: proposed field/action payload names are UI handoff requirements, not approved contracts. "Closed" deficiency items display the proposed RESOLVED state. Checklist/DSC/source metadata, available actions, concurrency versions and committee fields still need backend design; no official Annexure checklist or legal clause is fabricated.
- DEMO ASSUMPTION WF-004: the BPMN screen is a read-only explanatory route visualization, not a workflow engine. Conditional SHC, current stage and unavailable loop/source metadata must remain explicit. Ruleset comparison never changes a case pin, and missing metrics/source fields are unavailable rather than guessed.

## Transition grammar 1.1 (25 October 2026)

- DEMO ASSUMPTION TG-001: shared transition roles, guard identifiers, auxiliary-stage/resume mapping, action aliases and choice of terminal decisions are a configurable engineering proposal, not an APH mandate. Existing 22 route stage lists and clocks.on_submit are unchanged.
- DEMO ASSUMPTION TG-002: start_rescrutiny is an officer-triggered alternative to submit_compliance after a response exists, not a mandatory extra stage between DEFICIENT and RESCRUTINY. complete/scrutinise alias advance; authorised_revert aliases revert. Runtime handlers remain unimplemented.
- DEMO ASSUMPTION TG-003: letter type/decision compatibility and lists_deficiencies are explicit template values requiring confirmed decision data. Demo defaults issue_loa/issue_eoa -> APPROVED, issue_lod -> REJECTED, and lists_deficiencies=false are NOT verified APH rules. P2 owns the subsequent letter/obligation logic; EOA_DEFICIENCY_6M is not opened directly by these templates.
- DEMO ASSUMPTION TG-004: decision templates close live AICTE_PROCESSING as MET and live INSTITUTION_RESPONSE as WAIVED. Conditional if_live requires a P2-approved inspection integration before runtime execution; no P2 schema write/read bypass is permitted. Existing INTERNAL durations stay P2 demo assumptions. No EVC duration or timer rule is invented.
- DEMO ASSUMPTION TG-005: revert targets only earlier actually visited nonterminal stages with coded reason and conditional second approval. Terminal reopening is prohibited in grammar v1; future policy needs explicit review. Exact reason-code values are not invented here.
- DEMO ASSUMPTION TG-006: static graph analysis is potential reachability over conditional/guarded edges, not a proof of feasible runtime guard assignments. Optional SHC selection and at_last_applicable_stage must be resolved by the future executor. wf.transition_applied and RuleSet workflow exposure remain proposed contract changes; no new events are emitted or API fields exposed by task 1.1.

## Workflow persistence 1.2 (25 October 2026)

- DEMO ASSUMPTION WP-001: startup materializes reproducible source definitions as DRAFT, never APPROVED/ACTIVE. YAML verified_text is source provenance, not lifecycle authorization. This bootstrap has no user command/API and performs no approval, activation or new domain event emission.
- DEMO ASSUMPTION WP-002: the source checksum covers sorted relative paths and SHA-256 hashes of routes/deadlines plus every inherited overlay/base file. Existing keys are immutable even for whitespace changes; publish a new revision rather than rewrite cached definitions or pins. Definition UUIDs are deterministic UUID5 values, not random IDs.
- DEMO ASSUMPTION WP-003: original StageVisit stays mapped in intake to preserve boundaries; wf_0002 renames its stored left_at to exited_at while retaining the ORM synonym. Existing timestamps survive migration. Entered times use existing intake ClockPort calls; record_exit uses ClockPort and requires an authorized caller/ledger command in future runtime work.
- DEMO ASSUMPTION WP-004: case_state is the schema foundation for future workflow commands, not a second writer wired into today's intake submit service. Pins are immutable at the database level and route/key references must exist; future command wiring uses agreed ports. Source sync never updates case_state or its optimistic version.
- DEMO ASSUMPTION WP-005: route_def clause_citation remains null unless the YAML route explicitly supplies clause_citation. Ruleset-level source metadata is stored separately, avoiding false Table 2.3 citations for Chapter I routes. No APH clause or legal deadline is invented.
- DEMO ASSUMPTION WP-006: demo-only overlays are imported only in demo mode; a demo-only default is rejected outside it. Created/approved/note metadata contains opaque UUID references only. The bootstrap actor reference is a deterministic technical reference, not a real person or an existing identity-provider account.

## Workflow engine 1.3 (25 October 2026)

- DEMO ASSUMPTION WE-001: the engine executes persisted potential edges only after resolving optional applicability, visit history and registered guards. Fact providers are trusted server wiring, not client payloads. Unknown checklist/deficiency/assignment/reason/decision/applicability/live-clock facts fail closed; their real backends remain later tasks.
- DEMO ASSUMPTION WE-002: P3 must define case.<canonical_action> policy. Its current unknown-action denial is preserved. CasePort resolves only owner/region before the authorization decision; case_state is locked afterward. Caller actor must exactly match the trusted uow principal; execute is an internal entry point, not an unauthenticated endpoint.
- DEMO ASSUMPTION WE-003: WF_ENABLE_LETTER_ISSUANCE defaults false and blocks letter transitions before effects. Enabling requires a real CompliancePort plus confirmed letter/decision facts; tests explicitly enable it with fakes. DRAFT definitions run only in demo mode; non-demo requires APPROVED/ACTIVE and refuses demo_only.
- DEMO ASSUMPTION WE-004: terminal statuses clear current_stage and close the old visit; they do not create a fake Stage. One transition event records the case/version change; each changed visit has its own exited/entered event. Submit preserves its existing event schema. All notes stay in NotesPort; no prose enters event payloads.
- DEMO ASSUMPTION WE-005: timer command.now uses one ClockPort instant; event_seq is null because workflow events follow timers in the requested order and Anchor permits null. Confirmed letter dates anchor at midnight Asia/Kolkata. Conditional close requires authoritative live-clock facts rather than P2 table reads or a new unapproved port method.
- DEMO ASSUMPTION WE-006: workflow uses an isolated Core Table view of its P1-owned wf.stage_visit physical schema, checked against the authoritative intake mapping, without importing intake business internals or adding a second table. New visit UUIDs are deterministic from application/version/target. Existing intake HTTP/application projections are not silently rewritten by this internal engine.
- DEMO ASSUMPTION WE-007: named checklist_complete guard is now registered and statically recognized, but existing r1 YAML/checksums are not rewritten to activate a new guard. New published rulesets may declare it after checklist integration. Same expected-version replay conflicts; P3's idempotency middleware remains above the engine.

## Case API 1.4 (25 October 2026)

- DEMO ASSUMPTION CA-001: the user explicitly authorized only a narrow platform/auth.py change for case-action permissions and RO region checks. The action-role sets mirror the existing proposed r1 YAML; per-stage guards remain authoritative. Unknown actions stay forbidden. API and collection scope also checks CasePort-derived institution/region, before pagination/counting.
  This resolves the missing case-action policy noted in WE-002 and plan 1.3; trusted guard/clock fact integrations remain outstanding.
- DEMO ASSUMPTION CA-002: existing intake applications without case_state have a read-only transient version-1 view. Draft routes are previews (ruleset_key null, preview_ruleset_key explicit). First successful action materializes the state under an application row lock, using a submitted application's existing pin or the default for draft submit. Projection/state/visits/deadlines/ledger commit together. Existing intake submit is adopted without replaying its events/clocks.
- DEMO ASSUMPTION CA-003: opened_deadlines contains actual port-returned deadline_id/rule_id pairs. closed_deadlines contains subject_id/rule_id/outcome because DeadlinePort.close returns no deadline ID. Pause/resume are not misreported as opens/closes. No P2 storage is read. This response shape needs P3 client agreement.
- DEMO ASSUMPTION CA-004: Idempotency-Key is optional and documented as reserved; it is not an implemented replay cache. Consumed expected versions still return 409. HTTP accepts note only as explicit prose; guard facts, actor identity and arbitrary payload text are rejected. Missing trusted fact providers still fail closed; tests inject fictional facts but use real auth/database/deadlines/ledger/timeline.
- DEMO ASSUMPTION CA-005: the requested successful submit -> scrutinise -> record_deficiency order is incompatible with pinned YAML. scrutinise aliases advance and leaves SCRUTINY; deficiency is allowed only at SCRUTINY. Tests prove that rejection and the valid submit -> record_deficiency -> submit_compliance -> scrutinise route. No legal rule or YAML transition is invented to make the requested sequence pass.
- DEMO ASSUMPTION CA-006: case pages sort application UUIDs; stage history sorts entered_at then visit UUID to break logical-clock ties deterministically. Collection scope currently resolves each candidate through CasePort (no unapproved batch port or cross-module query); this is appropriate to the demo dataset and needs a future port design for large datasets. No shared contract change beyond the authorized OpenAPI regeneration.
